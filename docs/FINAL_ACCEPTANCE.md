## 现场验收步骤

每个测试启动前先保存终端日志。请在项目目录运行：

```bash
cd ~/edge_inspector/05_face_attendance
mkdir -p acceptance_logs
bash ./run_face_attendance.sh 2>&1 | tee "acceptance_logs/run_$(date +%Y%m%d_%H%M%S).log"
```

### 1. 已录入人员 person_a（合成示例）

1. 由 `person_a` 对应的授权测试者面对摄像头，保持单人、正脸、稳定光照。
2. 界面应先显示 `身份确认中 1/3`，随后显示 `测试匹配：person_a（001）`。
3. 终端应有 `test_confirmed= true`；首次在场时应显示测试打卡成功或今日已打卡。
4. 离开画面超过1.5秒，姓名应消失，界面回到未检测到人脸或身份未确认。

通过标准：只确认 `person_a`，不显示 `person_b`；离开后不保留姓名。

### 2. 已录入人员 person_b（合成示例）

1. 由 `person_b` 对应的授权测试者单独面对摄像头。
2. 重复测试1的观察步骤。
3. 终端候选和界面最终身份应是 `person_b`（002）。

通过标准：只确认 `person_b`，不显示 `person_a`。若未通过，记录分数、第二名分数、分差、姿态、距离、光照，不要立刻修改阈值。

### 3. 未录入人员拒识

1. 由未录入且知情同意的真人单独面对摄像头。
2. 等待至少5秒，观察状态和终端候选日志。

通过标准：不得显示“测试匹配：person_a/person_b”，不得产生针对两名已录入示例人员的新考勤。界面可以显示“身份未确认”。

不要用屏幕照片、手机照片或视频代替真人测试。当前没有活体检测，无法以该测试证明防照片攻击能力。

### 4. 多人、人脸缺失和画面恢复

1. 两名真人同时入镜。
2. 界面应显示“检测到多人，请单人面对摄像头”，不确认身份或打卡。
3. 所有人离开画面，状态应清除；30秒后屏幕变黑。
4. 一人重新入镜，屏幕应唤醒，恢复检测和确认。

通过标准：多人时无姓名确认；无人时旧姓名不残留；重新入镜后正常恢复。

### 5. 人员与样本管理

1. 单人面对摄像头后点击录入人员。
2. 选择编辑工号，输入已有的示例工号 `001`，确认弹窗应显示 `person_a`；点击取消。
3. 查询样本数，确认取消没有新增记录。
4. 再次确认追加一条样本，运行中应输出新的 `Gallery ready`，人员数仍为2、样本数增加1。
5. 在管理中删除刚才新增的样本，图库再次自动刷新；原有基线样本保留。

通过标准：已有工号不能创建第二个人；取消不写库；追加和删除都不需要重启。

### 6. 记录和导出

1. 管理 -> 考勤记录，确认记录中姓名、工号、日期和首次打卡时间显示正确。
2. 导出全部 CSV。
3. 在电脑上使用“数据 -> 从文本/CSV”导入，将工号列设为文本。
4. 比对 CSV 条数、记录内容和数据库查询结果。

```bash
sqlite3 -header -column data/attendance.db \
  "SELECT d.id,p.name,p.employee_no,d.attendance_date,d.check_time,d.similarity,d.is_test
   FROM daily_attendance d JOIN persons p ON p.id=d.person_id
   ORDER BY d.id;"

sqlite3 data/attendance.db "SELECT COUNT(*) FROM daily_attendance;"
```

通过标准：CSV含 UTF-8 BOM、工号显示为001、时间保留 `+08:00`，记录数与第二条查询一致。

## 发布前边界

在所有必测项通过前，项目应称为“端侧人脸考勤原型”或“开发测试系统”，不应称为安全认证、商用考勤或具备活体防伪的系统。GitHub 不应提交 `data/attendance.db`、`backups/attendance.final.db`、`exports/`、`perf_logs/`、人脸 PNG、对齐图片、特征文本或含个人信息的CSV。
