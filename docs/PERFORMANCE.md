# 性能与稳定性说明

本文记录 Orange Pi 5（RK3588）单路人脸考勤原型的实测结果与实现边界。它描述开发测试环境的表现，不代表多人、高温、长时间或安全认证场景的性能承诺。

## 运行配置

| 项目 | 配置 |
|---|---|
| 平台 | Orange Pi 5，RK3588，Linux 6.1.43-rockchip-rk3588 |
| 显示 | linuxfb 原生 720 x 480，应用使用 480 x 720 竖屏逻辑坐标 |
| 摄像头 | `/dev/video-camera0`，V4L2 NV12，720 x 480，stride 720 |
| 人脸检测 | RetinaFace mobile 320，`RetinaFace_mobile320_rk3588.rknn` |
| 人脸识别 | MobileFaceNet，`w600k_mbf_rk3588.rknn`，512维特征 |
| 运行时 | RKNN Runtime，Qt 5，OpenCV（人脸仿射对齐） |
| 检测输入 | 保持纵横比的 320 x 320 letterbox，RGB 转 BGR 后提交 RKNN |
| 识别输入 | 五点关键点仿射对齐后的 112 x 112 图像 |

程序检测与识别使用的不是 YOLO。项目准确表述为：RK3588 NPU 加速 RetinaFace 人脸检测、五点对齐和 MobileFaceNet 特征比对。

## 数据流与背压策略

```text
V4L2 NV12 摄像头
  -> 采集线程
  -> 单槽 latestFrame（新帧覆盖旧帧）
  -> 推理线程：检测 -> 对齐 -> 特征 -> 比对
  -> 结果帧与时间戳
  -> Qt 显示线程 / 每日考勤写入
```

采集线程、推理线程和界面线程相互分离。采集端只保留最新一帧，推理慢于采集时旧帧会被主动丢弃，而不是进入无界队列。因此系统优先实时性，不能保证处理每一帧。推理结果和显示端均检查时间戳；画面超过一秒未更新时显示超时提示，识别确认也有独立有效期。摄像头采集失败会停止采集并在界面提示错误。

这不是完整的“永不卡死”证明。进程崩溃可以由可选的 systemd `Restart=on-failure` 方案恢复，已验证一次 SIGKILL 后服务重新启动；进程仍存活但采集线程异常或设备驱动卡住，需要后续通过心跳/错误退出策略处理。可选部署方法见 `DEPLOYMENT_SYSTEMD.md`。

## 基线采样

采样于 2026-09-15。摄像头保持单人、稳定光照和正常散热条件；程序运行约五分钟。`perf_sample.sh` 每秒读取温度、CPU频率、内存和线程快照，应用日志每秒汇总检测/推理信息。

| 指标 | 结果 |
|---|---:|
| 推理 FPS 平均值 | 29.90 FPS |
| 推理 FPS 范围 | 25.94 至 30.98 FPS |
| 推理循环平均耗时的均值 | 19.47 ms |
| 单个一秒窗口内最大推理耗时 | 135.69 ms |
| SoC 温度 | 41.6 至 47.2 C |
| CPU 热区温度 | 41.6 至 48.1 C |
| NPU 热区温度 | 41.6 至 46.2 C |
| GPU 热区温度 | 40.7 至 46.2 C |
| CPU 频率观测范围 | 408 至 2352 MHz |

该轮日志没有出现摄像头采集失败、画面更新超时或 RKNN 检测调用失败。出现过“对齐误差过大”的拒绝记录，这是姿态/关键点质量门限拒绝，不能解释为推理系统卡死。

温度处于较低范围，结合接近30 FPS的稳定吞吐，本次条件下没有观察到明显热降频导致的性能下降。该结论不覆盖封闭外壳、高环境温度或超过五分钟的连续负载。

## 检测分段测量

为避免终端输出污染测量，检测器的逐帧 `conf[...]` 调试打印已通过默认关闭；保留 `ATTENDANCE_DEBUG_SCORES=1` 用于定位模型输出。分段日志按约一秒汇总，共分析173个有效窗口。

| 检测阶段 | 每秒窗口平均值的均值 | 全部窗口中的最大单次值 |
|---|---:|---:|
| 预处理：RGB转换、缩放、letterbox、BGR重排 | 6.420 ms | 33.205 ms |
| `rknn_inputs_set` | 8.150 ms | 49.607 ms |
| `rknn_run` | 3.925 ms | 15.459 ms |
| `rknn_outputs_get` | 0.401 ms | 2.426 ms |
| RetinaFace解码/阈值筛选 | 0.030 ms | 0.171 ms |
| 输出释放与NMS | 0.003 ms | 0.049 ms |
| 检测总耗时 | 18.937 ms | 91.604 ms |
| RKNN 调用失败 | 0 | 0 |

因此，平均检测耗时主要来自 CPU 图像预处理与 `rknn_inputs_set` 输入提交，而不是 NPU `rknn_run` 或检测后处理。较大的检测峰值也主要落在预处理/输入提交路径。NMS不需要优先优化。

人脸对齐和特征提取只在满足单人脸、尺寸和有效期条件时按约每秒一次执行，因此不能和每帧检测耗时直接相加比较。修正计时边界后，它们通常为约 0.1 至 2.4 ms（对齐）和约 3.9 至 6.1 ms（特征提取）；这组数值用于量级判断，不是完整端到端平均值。

## NPU 负载与频率

当前镜像提供节点：

```text
/sys/devices/platform/fdab0000.npu/devfreq/fdab0000.npu/load
```

其格式为 `负载百分比@频率Hz`。在第二次五分钟采样的第295至299秒，连续观测到：

```text
100@1000000000Hz
```

即这五秒内 NPU 负载为100%，频率为1 GHz，等于该节点报告的最大频率。它证明持续检测时NPU被充分使用，但这是每秒轮询快照，不能推断五分钟内每一秒都保持100%，也不能精确描述亚秒级峰值。

`perf_sample.sh` 已记录 `npu_load_percent` 与 `npu_frequency_hz`，后续长时间或热环境测试可以基于同一脚本做趋势分析。

## RKNN 内存与零拷贝结论

已确认本机的 `rknn_api.h` 与 `librknnrt.so` 同时提供：

```text
rknn_create_mem
rknn_destroy_mem
rknn_mem_sync
rknn_set_io_mem
rknn_create_mem_from_fd
```

RetinaFace 模型查询结果显示，输入张量有307200个元素但占614400字节；三个输出也是每元素2字节。Runtime 暴露的 tensor 属性报告为 `type=1`、`qnt=2`、`scale=1`、`zp=0`。这说明当前普通输入路径从提交的 uint8 BGR 图像到模型原生张量之间存在运行时转换/拷贝；它**不能单独证明模型权重是否量化**，也没有替代正式精度评估。

当前没有使用：

- V4L2 DMA-BUF 到 RGA 到 RKNN 的端到端零拷贝路径。
- RGA 硬件颜色转换、缩放或仿射变换。
- RKNN tensor-memory 输入输出路径。

仅替换为 `rknn_set_io_mem` 不能消除 QImage 预处理，且必须正确处理原始16位输出；在CPU手动转换输入数据后不一定更快。完整DMA-BUF方案还需要改造V4L2 buffer管理和引入RGA。因此这些优化没有合入稳定主版本。

## 模型、后处理与精度边界

检测器按 RetinaFace 的4200个先验框解码位置、置信度和五点关键点，只保留分数不低于0.50的候选，并使用 IoU 0.40 的NMS。它输出所有未被NMS抑制的人脸，主流程在录入和识别时要求恰好一张有效人脸。

MobileFaceNet 生成512维特征并做L2归一化，以余弦相似度排序。当前测试数据中，同一人两张静态样本相似度为0.881996，不同人样本为0.176417；实时确认还要求分数、第二名差距与连续命中次数。这些少量样本不能构成正式 FAR、FRR、ROC 或量化精度评估。

项目没有对检测模型或识别模型做系统性的量化前后精度对比，也没有活体检测、防照片攻击或管理员权限机制。系统目前写入的是测试考勤记录，不能用于需要身份安全保证的正式考勤。

## 结论与后续优化

在单路720 x 480摄像头、正常散热、稳定单人画面的实测条件下，系统达到约30 FPS，未观察到队列积压、持续降频、RKNN检测调用失败或画面超时。当前版本满足单路端侧演示和原型考勤的实时性目标。

后续优化应保持独立实验分支，并以对比数据决定是否合并：

1. 先做更长时间和更高环境温度下的采样，观察温度、NPU频率、FPS与峰值延迟。
2. 评估复用普通输入缓冲，减少每帧 `std::vector` 分配；先保持 `rknn_inputs_set` 语义不变。
3. 若预处理仍是主要瓶颈，再建立 RGA 缩放/颜色转换 benchmark，与当前QImage路径对比延迟、CPU占用、检测结果和稳定性。
4. 仅在具备V4L2 DMA-BUF、RGA和正确RKNN tensor-memory适配后，实验端到端零拷贝；不将“支持API”表述为“已实现零拷贝”。
5. 用独立测试集评估量化前后检测/识别精度，以及不同光照、姿态、距离、陌生人和多人场景下的误识与拒识。

采样操作、字段含义和复现实验命令见 `PERFORMANCE_SAMPLING.md`；RKNN tensor-memory检查见 `ZERO_COPY_CHECK.md`。
